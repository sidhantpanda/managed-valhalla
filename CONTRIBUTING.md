# Contributing

Thanks for helping improve valhalla-manager. Bug reports, fixes, docs and new features are all welcome.

## Before you start

- For anything bigger than a small fix, open an issue first so we can agree on the approach.
- Search existing issues and pull requests to avoid duplicate work.
- By contributing, you agree that your contributions are licensed under the [MIT License](LICENSE).

## Repository layout

| Path | What it is |
|---|---|
| `compose.yaml` | The two-container stack |
| `valhalla/start.sh` | Entrypoint for the serving container: applies limits and restarts Valhalla when new tiles appear |
| `valhalla-admin/` | Next.js admin that downloads regions and builds tiles |
| `valhalla-admin/lib/server/` | Server code: region catalog, build pipeline, state on disk |
| `valhalla-admin/components/` | Admin UI |

## Running the stack

```sh
docker compose up -d --build
docker compose logs -f
```

Use a small region such as `europe/monaco` (set `VALHALLA_DEFAULT_REGIONS` in `.env`) so builds finish in seconds while you test.

## Working on the admin

Requires Node 24 and pnpm (enable it with `corepack enable`).

```sh
cd valhalla-admin
pnpm install
pnpm build    # type-checks and builds; CI runs this
```

The tile build tools (`valhalla_build_tiles`, `osmium` and friends) only exist inside the Docker image, so test build changes with `docker compose up -d --build valhalla-admin` rather than `pnpm dev`. `pnpm dev` is fine for UI work.

`valhalla-admin/AGENTS.md` is generated by `next dev`; leave it in place.

## Pull requests

- Keep each pull request focused on one change.
- Describe what changed and how you tested it. For build pipeline changes, say which regions you built.
- Make sure `pnpm build` passes and `docker compose config` is valid. If you change `valhalla/start.sh`, run `shellcheck` on it.
- Update `README.md` when behaviour or configuration changes.

## Reporting security issues

Don't open a public issue. See [SECURITY.md](SECURITY.md).
